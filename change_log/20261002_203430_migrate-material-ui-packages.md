# Change log: Migrate to the standalone material_ui and cupertino_ui packages

Implements plan: `plans/20261002_202809_migrate-material-ui-packages.md`

## Summary

The app now uses the standalone `material_ui` and `cupertino_ui` packages instead of the
frozen `package:flutter/material.dart` and `package:flutter/cupertino.dart` libraries in
the Flutter SDK. A lint rule now blocks the old imports.

## What changed

### Dependencies and config
- `pubspec.yaml` — added `material_ui: ^1.5.0` and `cupertino_ui: ^1.1.1` as direct
  dependencies, with a comment. Both were already in the lock file as indirect
  dependencies, so no other package versions changed.
- `pubspec.lock` — the two entries changed from indirect to direct.
- `analysis_options.yaml` — added the `migrate_design_widgets: true` lint rule.

### Import rewrite
- `dart fix --apply --code=migrate_design_widgets` made 70 fixes in 69 files under `lib/`
  and `test/`: one import line per file. No old design imports are left.

### Localization (the manual part)
We found that the 3.47 `flutter gen-l10n` template still writes the **old** SDK
`GlobalMaterialLocalizations` / `GlobalCupertinoLocalizations` delegates into the generated
`AppLocalizations.localizationsDelegates`. These give old-type localizations, which the new
`material_ui` widgets cannot see. A test proved it: with the generated list, Material
localizations were missing for Malayalam and Sanskrit.

The plan's "clean fix" option was applied:
- `lib/core/locale/locale_config.dart` — new `LocaleConfig.localizationsDelegates`. It
  holds the Sanskrit fallback delegates, `AppLocalizations.delegate`, and the new
  `GlobalMaterialLocalizations.delegates` from `material_ui` (which also includes the
  Cupertino and Widgets delegates).
- `lib/main.dart` — `MaterialApp.router` now uses `LocaleConfig.localizationsDelegates`.
- `lib/l10n/sa_material_localizations.dart` — the Material/Cupertino delegates now come from
  `material_ui` / `cupertino_ui`. Only `GlobalWidgetsLocalizations` is still imported from
  `flutter_localizations` (it did not move). The Sanskrit-to-English fallback works the same
  as before.
- `lib/l10n/app_localizations.dart` — regenerated by `flutter gen-l10n`, not edited by hand.
  Its `localizationsDelegates` list is no longer used anywhere.
- `flutter_localizations` stays in `pubspec.yaml`. The generated l10n code and
  `material_ui` itself still depend on it.

### Tests
- 10 widget test files (`test/screens/*`, `test/widgets/counter_card_test.dart`) now use
  `LocaleConfig.localizationsDelegates` instead of the generated list. The three
  hand-built lists in `about_screen_test.dart` were replaced by the same constant.
- `test/core/locale/locale_config_test.dart` — 4 new guard tests:
  - Material and Cupertino localizations load for `en`, `ml` and `sa`.
  - Malayalam gets real Malayalam Material strings.

  We checked that these tests **fail** when the old generated list is used, so they really
  protect against this problem coming back.

### Docs
- `docs/architecture.md` (Theme section) — notes on the new packages and the delegate rule.
- `CLAUDE.md` (Code style) — two new rules: import `material_ui` / `cupertino_ui` only, and
  always use `LocaleConfig.localizationsDelegates`.
- `docs/guidelines/` (shared submodule) was not changed.

## Small differences from the plan
- `lib/core/locale/locale_config.dart` and the test files changed more than "one import
  line". This was the plan's planned fallback ("switching to the new
  `GlobalMaterialLocalizations.delegates`"), needed because gen-l10n has no
  `material_ui` support yet.
- The guard tests in `locale_config_test.dart` were added. They were not listed in the
  plan, but they cover the main risk the plan named.

## Verification
- `flutter analyze` — no issues.
- `flutter test` — all 216 tests pass (212 before, plus 4 new).
- **Not done yet:** the manual device check (plan step 9). Run `flutter run --flavor dev`
  and check dialogs, the History date picker, the text selection menu, the theme, and
  count saving in English, Malayalam and Sanskrit.

## Follow-up to watch
- When a future Flutter release teaches `gen-l10n` about `material_ui`, the generated
  `AppLocalizations.localizationsDelegates` may become safe again. Until then, keep using
  `LocaleConfig.localizationsDelegates`.
