# Change log: Upgrade to AGP 9.1.0, Gradle 9.3.1 and Kotlin 2.4.0

Implements plan: `plans/20261002_195120_upgrade-agp9-gradle9-kotlin24.md` (including "Update 1").

## Why

Flutter was upgraded from 3.44.8 to 3.47.6. Flutter 3.47.6 recommends Java 17, AGP 9.1.0,
Gradle 9.3.1 and Kotlin Gradle Plugin 2.4.0. The project was on AGP 8.11.1, Gradle 8.14 and
Kotlin 2.2.20.

## What changed

| File | Change |
|------|--------|
| `android/settings.gradle.kts` | AGP `8.11.1` → `9.1.0`; Kotlin `2.2.20` → `2.4.0` |
| `android/gradle/wrapper/gradle-wrapper.properties` | Gradle `8.14` → `9.3.1` |
| `android/app/build.gradle.kts` | `generateBuildMetadata` now uses Gradle's `ExecOperations` instead of `project.exec` (removed in Gradle 9). Same inputs, outputs, order and error message. Removed `id("kotlin-android")` from `plugins { }` to match the Flutter 3.47.6 template (the Flutter Gradle plugin applies Kotlin while `android.builtInKotlin=false`). |
| `android/build.gradle.kts` | New **temporary** block that applies the Kotlin plugin (Java 17 target) to the `file_picker` module only, and only while `android.builtInKotlin=false`. |
| `pubspec.lock` | `file_picker` 11.0.2 → 11.0.3 (inside the existing `^11.0.2` range). `flutter pub get` on the new SDK also refreshed some SDK-pinned packages. `pubspec.yaml` is unchanged. |
| `CLAUDE.md` | Added an "Android toolchain" row to the project identity table. |
| `analysis_options.yaml` | Changed by Flutter itself during the build: added `build/**` and `android/**` to the analyzer exclude list. Kept. |

`android/gradle.properties` is unchanged. It keeps `android.builtInKotlin=false`,
`android.newDsl=false` and `kotlin.incremental=false`.

## The `file_picker` workaround

`file_picker` 11.x skips the Kotlin plugin on AGP 9 because it expects AGP's built-in Kotlin.
This project must keep built-in Kotlin off, because `audioplayers_android`, `package_info_plus`,
`share_plus` and `shared_preferences_android` still apply the old Kotlin plugin. Without the
workaround, nothing compiles `file_picker`'s Kotlin code and the build fails with
`cannot find symbol ... FilePickerPlugin`. Version 11.0.3 has the same build logic, so the
version bump alone did not fix it.

**When to remove it:** once every plugin in Flutter's "plugins that apply KGP" warning
supports built-in Kotlin, set `android.builtInKotlin=true` (and remove `android.newDsl=false`
if Flutter's template does too), delete the block in `android/build.gradle.kts`, and retest.

## Verification

- `flutter analyze` — No issues found.
- `flutter test` — all 212 tests passed.
- `flutter build apk --flavor dev --debug` — built.
- `flutter build apk --flavor prod --release --obfuscate --split-debug-info=... --split-per-abi` — built (armeabi-v7a, arm64-v8a, x86_64) and signed with the release key (`apksigner verify` OK).

## Warnings seen in the build output (not fixed here)

- Flutter warns that `audioplayers_android`, `file_picker`, `package_info_plus`, `share_plus` and
  `shared_preferences_android` apply the Kotlin Gradle Plugin, and that future Flutter versions
  will fail to build with such plugins. Upgrade them when versions with built-in Kotlin support
  are released.
- Release builds print "The generated ELF library contains unobfuscated DWARF debugging
  information. To avoid this, use --strip to remove it." This is new with the Flutter upgrade.
  Consider whether to add `--strip` to the release commands in a separate change.
