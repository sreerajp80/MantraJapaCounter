# Raise compileSdk to 37 (keep targetSdk 36)

**Status:** completed

## Issue

The prod release build (`assembleProdRelease`) fails at `:app:checkProdReleaseAarMetadata`.

After `flutter pub upgrade`, these libraries now need the app to **compile against** Android API 37:

- `flutter_local_notifications` (23.0.0-dev.3)
- `androidx.core:core` 1.19.0 and `androidx.core:core-ktx` 1.19.0 (pulled in by the plugin)

The app sets `compileSdk = flutter.compileSdkVersion`, and Flutter currently gives 36. So the AAR
metadata check stops the build.

## Background

- `compileSdk` only decides which Android APIs the code can see at build time. It does not
  change how the app behaves on a phone, and it does not change which devices can install it.
- `targetSdk` is what turns on new runtime behavior. It must stay at **36**. `docs/release_process.md`
  warns that API 37 ignores the Android 16 portrait-lock opt-out
  (`PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY`). Raising `targetSdk` is a separate task.
- `minSdk` stays at 29.

## Files to change

1. `android/app/build.gradle.kts` — change `compileSdk = flutter.compileSdkVersion` to `compileSdk = 37`,
   with a short comment saying why (plugins need 37) and that `targetSdk` stays 36 on purpose.
2. `README.md` — the toolchain table says "compile/target SDK 36". Change it to
   "compile SDK 37, target SDK 36, min SDK 29".
3. `CLAUDE.md` and `AGENTS.md` — the Platform(s) row says "minSdk 29, targetSdk 36". Add
   "compileSdk 37" so the docs match the build file.

No Dart code, manifest, or test changes.

## Steps

1. Make the edits above.
2. Make sure Android SDK Platform 37 is installed (Android Studio → SDK Manager → SDK Platforms →
   Android API 37). Gradle may also download it on its own if SDK licenses are accepted.
3. Run `flutter analyze` and `flutter test`.
4. Run `flutter build apk --flavor prod --release` (or the user's normal release command) to
   confirm `checkProdReleaseAarMetadata` passes.
5. Write a change log in `change_log/`.

## Risks

- Low. `compileSdk` is backward compatible. The only side effect is that the build may show new
  deprecation warnings from API 37.
- When a future Flutter release sets `flutter.compileSdkVersion` to 37 or higher, we can switch
  back to `flutter.compileSdkVersion`.
