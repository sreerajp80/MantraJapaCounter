# Plan: Raise targetSdk from 35 to 36

**Status:** Implemented (see change_log/20260922_202500_target-sdk-36.md)

## Issue

Google Play Console rejected version code 29 with this error:

> Your app currently targets API level 35 and must target at least API level 36.

The app sets `targetSdk = 35` in `android/app/build.gradle.kts`. `compileSdk` already
comes from Flutter (`flutter.compileSdkVersion`), which is 36 in the installed Flutter
SDK, so only the target needs to change.

## Fix

1. `android/app/build.gradle.kts` — change `targetSdk = 35` to `targetSdk = 36`.
2. `pubspec.yaml` — bump version from `6.12.1+29` to `6.12.2+30`. Play does not accept
   the same version code twice, and code 29 may already be used by the rejected upload.
3. Update docs that state the target SDK:
   - `CLAUDE.md` — identity table: `targetSdk 36`.
   - `AGENTS.md` — identity table: `targetSdk 36`.
   - `README.md` — "compile/target SDK 36".
   - `docs/features.md` — "Target SDK 36 (Android 16)".

## Android 16 (API 36) behavior changes checked

- **Edge-to-edge opt-out removed.** The manifest does not use
  `windowOptOutEdgeToEdgeEnforcement`, so nothing changes. The app already runs
  edge-to-edge under API 35.
- **Predictive back on by default.** The code does not use the old `WillPopScope` or
  `onBackPressed`. Flutter handles back through `PopScope`, so this should be fine.
  Check back navigation on a device.
- **Orientation lock ignored on large screens.** On tablets and foldables (screen
  width 600 dp or more), Android 16 ignores the portrait lock set in `main.dart`.
  Phones are not affected. The app may rotate on tablets. No code change is
  planned; this is noted for testing.
