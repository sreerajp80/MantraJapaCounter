# Upgrade Flutter to 3.50.1 and Kotlin to 2.4.20

**Status:** completed

## What the issue is

The user asked to move the toolchain to:

| Tool | Now | Wanted |
|------|-----|--------|
| Flutter | 3.47.6 (Dart 3.13.5) | 3.50.1 (Dart 3.14.0) |
| AGP (Android Gradle Plugin) | 9.4.1 | 9.4.1 — already done, no change |
| Gradle | 9.8.0 | 9.8.0 — already done, no change |
| Kotlin Gradle Plugin | 2.4.10 | 2.4.20 |

Flutter 3.50.1 is already installed on this machine (`flutter --version`). The project files
and docs still say 3.47.6 and Kotlin 2.4.10. CI still pins Flutter 3.47.6, so CI would test
with a different Flutter than local builds.

## Files to change

| File | Change |
|------|--------|
| `android/settings.gradle.kts` | Kotlin plugin `2.4.10` → `2.4.20` |
| `android/app/build.gradle.kts` | Comment "matches the Flutter 3.47 app template" → 3.50 (only if the 3.50 template still applies Kotlin the same way; checked during the work) |
| `.github/workflows/ci.yml` | `flutter-version: 3.47.6` → `3.50.1` (release_process.md says to do this on every Flutter upgrade) |
| `CLAUDE.md` | Project identity table: Flutter 3.50.1, Dart 3.14.0 note, Kotlin 2.4.20 |
| `AGENTS.md` | Same table rows as `CLAUDE.md` |
| `README.md` | Prerequisites: Flutter 3.50.1 or higher |
| `docs/implementation_progress.md` | "Flutter SDK: 3.50.1+ / Dart 3.14.0+" |
| `pubspec.lock` | May change on `flutter pub get` (Flutter SDK pins some packages). No manual edit. |

Not changed:

- `pubspec.yaml` `environment: sdk: ^3.13.5` stays. It already allows Dart 3.14.0. Raising
  it would also raise the Dart language version, which can change `dart format` output and
  lints across the whole code base. That is better as its own change, so any breakage has
  one clear cause.
- `material_ui` / `cupertino_ui` are not upgraded here (release_process.md §16: never in the
  same change as a Flutter SDK upgrade).
- `docs/guidelines/` (read-only submodule). Its build-flavors guide still lists Flutter
  3.47.6 / KGP 2.4.0 as "last checked". I will write a note for the user instead of editing it.
- Old notes like "moved out of the Flutter SDK in 3.47" stay — they are history, still true.

## Plan for the fix

1. Edit the files in the table above.
2. Run `flutter pub get`, then `flutter gen-l10n` check, `dart format --set-exit-if-changed .`,
   `flutter analyze`, `flutter test`.
3. Run one dev build to prove Gradle + Kotlin 2.4.20 work:
   `flutter build apk --flavor dev --debug`.
   (Per the learning rule I will give the user the commands first and ask if they want to run
   them, unless they ask me to.)
4. After the build: `android\gradlew --stop`, then check no `GradleDaemon` /
   `KotlinCompileDaemon` process is left (end only those, never all `java.exe`).
5. Write the change log in `change_log/`.

## Risks

- Flutter 3.50 may add new lints or deprecations → `flutter analyze` may show new warnings.
  If so, I fix them only if small; otherwise I report them and ask.
- Flutter's migrator may touch `android/gradle.properties` or Gradle files on first build.
  I will look at any such change and report it.
- Kotlin 2.4.20 with `android.builtInKotlin=false`: low risk (patch-level bump).

**Security impact:** Build toolchain only (Gradle plugin version and CI Flutter version). No
new permissions, no network, no new dependencies. Low risk.
