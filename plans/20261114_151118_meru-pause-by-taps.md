# Plan: Meru pause by tap count

**Status:** completed

## The issue

Today the Meru pause is time-only. After each mala, a timer of 3, 5 or 10 seconds starts,
and all taps are ignored until it ends.

The user wants a second way: end the pause after a set number of taps. Example: with
"2 taps", the first 2 taps after a mala are not counted, and the 3rd tap counts again.

Chosen design (agreed with the user): **pick one — Time or Taps.**
- In **Time** mode nothing changes.
- In **Taps** mode there is no timer. The next N taps after a mala are not counted. When the
  last pause tap is made, the pause ends and counting starts again with the next tap.

## Design details

- New pure-Dart enum `MeruPauseMode { time, taps }` with a string id and `fromId()`, the same
  pattern as `MalaSound`. Unknown or missing saved value → `time` (so current users see no
  change).
- Tap count: **no fixed choices**. The user sets any whole number from **1 to 19** (less than
  20). Default **2**. A saved value outside 1–19 (or missing) → default 2.
- Settings screen (Display & Stillness → Meru pause, shown only when the switch is on):
  1. A row of two chips: **Time** / **Taps**.
  2. Below it: in Time mode the same `3 s / 5 s / 10 s` chips; in Taps mode a small stepper
     `[ − ]  2 taps  [ + ]`. `−` is disabled at 1 and `+` is disabled at 19, so a wrong value
     can never be entered. (A stepper is chosen over a text box: no keyboard, no typing
     errors, and no need for an error message.)
- Counting screen overlay in Taps mode:
  - Same lotus, "Pause · Breathe" and message.
  - The ring shows taps left (for 2 taps: full → half → gone) instead of running down with
    time.
  - One extra small line: "2 taps left" / "1 tap left" (plural from ARB).
- Pause taps do not vibrate and do not play a sound (same as today's ignored taps). The
  overlay line and the ring are the feedback.
- Undo swipe and leaving the screen still end the pause at once (unchanged `endMeruPause`).
- Settings are not part of the backup file, so the backup format does not change.

## Steps

1. Add the enum, constants, repository and settings provider fields.
2. Change `CountingNotifier` (`_startMeruPauseIfMalaDone`, `tap()`).
3. Add ARB keys in all three languages, run `flutter gen-l10n`.
4. Update the settings screen and the overlay.
5. Add/update tests.
6. Update docs.
7. `dart format .`, `flutter analyze`, `flutter test`.
8. Write the change log.

## Security impact

None. Only two new local SharedPreferences keys. No network, permissions, or backup format
change.
