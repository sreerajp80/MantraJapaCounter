# Plan: Improve R8 shrinking and optimisation

**Status:** Skipped (2026-09-22) — the size gain is small and not worth the testing risk right now

## Issue

The Play Console App Bundle Explorer shows:

- Optimisation percentage: `-` (red icon)
- Shrinking percentage: `-` (red icon)
- R8 "Resource shrinking optimised": off
- R8 "Repackage classes": off
- Hint: "Upgrade to AGP version 9.0 to get the best performance"

This is **not** a release blocker. It is advice.

R8 only handles the Java/Kotlin part of the app (Flutter embedding + plugins). The Dart
code is compiled to native code in `libapp.so` and is obfuscated by `--obfuscate`, not
by R8. So the size gain from this work is small (likely a few hundred KB at most).

The main cause of the poor numbers is `android/app/proguard-rules.pro`. It keeps
whole packages with every class and member:

```
-keep class io.flutter.** { *; }
-keep class io.flutter.plugins.** { *; }
-keep class com.tekartik.sqflite.** { *; }
-keep class com.google.android.play.core.** { *; }
```

These rules stop R8 from removing or optimising anything in those packages. They are
not needed:

- Flutter's Gradle plugin already adds its own rules (`flutter_proguard_rules.pro`),
  and the Flutter engine jar ships the rules it needs. New Flutter projects have no
  custom rules at all.
- Plugins such as sqflite are registered by direct calls in
  `GeneratedPluginRegistrant`, so R8 can see they are used.
- The Play Core classes are not in the app. Only `-dontwarn` is needed for them.

## Fix

1. `android/app/proguard-rules.pro`
   - Remove the four broad `-keep class ... { *; }` rules.
   - Keep `-dontwarn com.google.android.play.core.**`.
   - Add `-repackageclasses` so R8 moves renamed classes into one package (turns on
     "Repackage classes").
2. `android/gradle.properties`
   - Add `android.r8.optimizedResourceShrinking=true` (turns on "Resource shrinking
     optimised"; this is the default in AGP 9).

## Not in this plan

- **Upgrading AGP to 9.0.** AGP 9 needs Gradle 9 and changes the Kotlin and DSL setup
  (see the `android.builtInKotlin` and `android.newDsl` flags the Flutter migrator
  added). Plugins may not all support it yet. This should be a separate plan when
  Flutter officially supports AGP 9.

## Risk

If R8 removes a class that is only reached by reflection or from native code, the
release build could crash at runtime. Debug builds do not use R8, so they will not
show this. The release build **must** be tested on a real device before upload.

## Verification

- `flutter analyze` and `flutter test` pass.
- `flutter build apk --flavor prod --release --obfuscate --split-debug-info=build/symbols/android-prod-v6.12.2/ --split-per-abi`
  builds with no R8 errors.
- Install the release APK on a device and test: app start, counting, saving
  sessions, notifications, reminders, import/export, share, settings, About.
- Compare the APK size before and after.
- If anything breaks, add a narrow keep rule for that one class (not a whole package).
